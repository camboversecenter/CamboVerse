# Preparing local updates for Git

Application source, generators, reviewed output-free notebook templates and
project documentation remain versionable. Reviewed application assets such as
the authored village GLBs, UI artwork and licensed province media also remain
eligible. They are different from raw training photos and capture experiments.

The root `.gitignore` keeps the following local:

- Capture/training data under `data/`, `NUM status/`, and `num-status-split/`.
- ZIP archives, camera originals/videos, splats, point clouds, training
  checkpoints, and Blender authoring intermediates.
- Everything in `public/models/local/` except its README: private captures,
  room panoramas, model evaluations and generated assets awaiting review.
- `output/`, `tmp/`, local helper runtimes/settings, caches and logs.
- Credentials/environment files, keys, authentication snapshots and HAR files.
- Personal Word/PowerPoint/PDF documents saved in the repository root.
- Downloaded/executed notebook backups and temporary extracted training cells.

The two already committed synthetic `angkor-wat.splat` / `wat-phnom.splat`
demo clouds remain allowed. They are generated by repository scripts, not
training media; the checker pins their hashes to catch an unreviewed replacement.

Ignoring preserves the files on disk. It does not erase earlier commits, block
`git add --force`, or make private assets safe to publish on a website.

## Local check

Run `npm run check:publish` before preparing a commit. It scans currently tracked
and untracked eligible files, plus actual staged content, for private paths, common credential patterns,
signed URLs and saved notebook outputs. It prints locations/categories, never
credential values. `npm run test:publish` exercises the checker.

After staging your intended changes, run:

```sh
node scripts/check-publish-safety.mjs --staged
git diff --cached --stat
```

The staged check reads the actual staged content, even if the working copy
differs. Pattern scanning is an aid, not a guarantee; it does not review image
contents, embedded metadata or all possible secret formats. If a real secret
was previously committed, revoke/rotate it and separately plan history cleanup.
Do not rewrite shared Git history without coordinating with collaborators.
`node scripts/check-publish-safety.mjs --history` separately checks common
credential patterns in reachable local text history, with file/revision/line
reports only. It skips media, binary data and text blobs above 8 MiB; it does
not contact the remote service or inspect its caches, forks or deleted refs.

## Existing photo history and local assets

At preparation time, 1,764 previously tracked files under `NUM status/` are
already missing in the working tree. Preserve/review those pending deletions;
committing their removal stops them appearing in the next revision but does
not remove copies from Git history. No history rewrite is part of this setup.

Many feature pages currently reference ignored `/models/local/` files, including
the room panoramas and heritage review models. They continue working on the
local machine. A Git push of source does **not** include these files, and a clean
checkout cannot reproduce every private preview without separately supplied
assets. Model downloads must pass privacy/licensing/provenance review before
being promoted to published asset paths. A successful code build alone does not
establish that those private previews are ready for a public deployment.

Also review hosting separately: Vite can copy files from `public/` into a local
build even when Git ignores them. Do not upload a locally built `dist/` containing
unreviewed private media. No push, deployment, commit, staging, branch change or
history rewrite is performed by the check commands.
